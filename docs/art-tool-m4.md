# M4 簡易GUI

2026-09-14。R18〜R20を実装し、Qtの操作テストと実GPUでの検証を完了した。
元動画の区間指定、効果の調整、同期比較、設定保存、書出しと取消を一つの画面から操作できる。

## 配置先の選定

このリポジトリのPython処理基盤を直接呼び出す、独立したPySide6 GUIを採用した。
既存Qt GUIは別リポジトリにあり、この作業ツリーには含まれていない。
以下は今回の配置先を決めるための比較であり、外部Qt GUIの実装を調査・計測した結果ではない。

| 条件 | 新しいPython GUI | 別リポジトリのQt GUIを拡張 |
|---|---|---|
| 個人利用の実装範囲 | 既存の`configuration`、`run`、`Session`を直接利用 | 別ツリーの取得と既存画面への接続が必要 |
| 同期比較 | 保存済み元フレームと結果を同じフレーム順で表示 | 既存プレイヤーと元時刻の対応方法を追加調査する必要がある |
| Windows起動 | インストール済みのPythonとPySide6で起動できる | 別GUIのビルド・配布手順も維持する必要がある |
| 待ち時間 | M3の処理をワーカースレッドで実行し、Qtへ進捗を配送 | 同じ処理基盤に接続するなら推論時間の短縮は見込まない |

個人利用に必要な操作をこのツリー内で検証でき、推論や乱数の実装を増やさずに済むため、独立GUIを選んだ。
起動スクリプトは[art_gui.py](../scripts/art_gui.py)、Windowsのダブルクリック用は[start_art_gui.pyw](../scripts/start_art_gui.pyw)である。

## 起動と操作

検証環境はWindows、Python 3.14.3、PySide6 6.11.1、RTX 4070 Ti SUPER。
M3で使用したCLI、モデル、FFmpeg、基準記録が必要になる。
初回の依存導入と起動はリポジトリ直下で行う。

```powershell
python -m pip install -r scripts/art-gui-requirements.txt
python -B scripts/art_gui.py --input test/test.mp4 --recipe build/art/m1-source-color/melt-16/recipe.json --baseline-dir build/art/m2-baseline-2
```

依存導入済みなら`start_art_gui.pyw`のダブルクリックでも起動できる。
処理中に起動するCLIなどの子プロセスは、コンソール窓を開かない。
`.pyw`から起動した場合、画面操作中の想定外の例外はダイアログに表示する。
既定の実行ファイルは`build/art/install/bin/video2x.exe`、基準記録は`build/art/m2-baseline-2`。
画面から別のパスも選べる。

1. 元動画、開始秒、終了秒を指定する。終了が空欄なら末尾まで処理する。
2. 採用済みの`melt-16`などを「設定読込」で開き、入力・モデル内部・再入力・出力の各効果を調整する。
3. 「区間プレビュー」を押す。完了後、左に元映像、右に結果が表示される。「再生 / 一時停止」と「先頭へ」で比較する。
4. 選んだ値を「設定保存」で新しいJSONファイルに保存する。
5. 本番の開始・終了と保存先を指定して「本番書出し」を押す。全編は開始0、終了空欄にする。

プレビューと本番は、どちらも指定区間を本番の推論解像度・タイル条件で処理する。
異なるのは出力フォルダー名の`preview-`と`export-`であり、プレビュー用に解像度や効果を変更しない。
実行ごとに未使用のフォルダーを作り、既存の動画や実行記録を上書きしない。
完成品は`result.mkv`、同名の実行記録は`result.json`。
表示中の結果に使用した設定と結果のパスは、比較画面の下で確認できる。

seedは数値を変更するか「seedを再抽選」を押すまで固定される。
再抽選は生成を開始しない。「全創作効果を0に戻す」はseedを維持し、pass数を1に戻す。
時間変化の作用先は入力ノイズだけで、固定モードでは周期・位相・変調幅を操作できない。
重みの減衰は強度1まで。対応層や未対応モデルの検査にはCLIと共通の設定検査を使う。
数値欄と選択欄は、クリックかTabで選択するまでマウスホイールで値が変わらない。
左の設定欄の上でホイールを回すと、欄全体がスクロールする。

## 同期表示と保存内容

[比較プレイヤー](../scripts/art_gui_player.py)は、処理時に保存した`input.mkv`と完成品を同じフレーム順で復号する。
再生間隔と表示時刻には`source_timeline`の`display_start`と`display_end`を使う。
このため、区間先頭をまたぐフレームや可変フレームレートも左右で対応する。
表示だけを幅960画素以下に縮小し、先読みキューは2組に制限する。
一時停止中にウィンドウの大きさを変えた場合も、表示中のフレームを枠に合わせて拡大縮小する。
復号が追いつかない場合は左右を一緒に遅く再生する。実時間での再生速度は保証しない。

比較再生は無音。
本番の音声はM3と同じく`pcm`でPCM変換して保持し、`omit`で除外する。
音声を含む視聴は「出力先を開く」から完成品を外部プレイヤーで開いて行う。
このボタンは比較画面に表示中の結果のフォルダーを開き、後の実行が失敗や取消で終わっても開く先を変えない。
任意フレームへのシーク、設定全体のランダム化、未対応モデルの選択は今回の対象外とした。

GUI設定JSONには、版番号、M2レシピ、元動画・区間・出力倍率・音声・基準記録・CLI・保存先の全操作値を保存する。
パスは保存時に絶対パスへそろえるため、起動時の作業フォルダーが変わっても同じファイルを参照する。
既存のM1/M2レシピ単体も読み込める。その場合、区間やパスは現在の値を維持する。
GUI設定JSONはGUI用の形式で、CLIへ渡すレシピには各出力フォルダーの`recipe.json`を使う。
読み込んだ効果値は、小数表示の桁数より精密な値であっても、編集するまで元の数値を保持する。
不正なGUI設定やモデル不一致は、画面へ適用する前に拒否する。

## 実行状態と取消

[実行管理](../scripts/art_gui_worker.py)は要求ごとに設定をコピーし、専用の`Session`と`QThread`を作る。
処理中も設定は編集できるが、実行中の要求には反映しない。
表示中の結果と現在の設定が違う場合は「設定変更あり」と表示する。
保存先フォルダーは結果の内容に影響しないため、この比較から除く。

進捗はQtのシグナルでUIスレッドへ配送する。
総数が不明または推定の場合は不定進捗にし、フレーム数が推定総数に達しても成功扱いにしない。
成功は共通APIが検証済みの実行記録を返した後に表示する。
失敗時は原因と出力先を表示し、直前の成功結果を維持する。

取消は`Session.cancel()`へ接続する。
取消要求済みの完了通知と、現在の要求IDに一致しない通知を結果表示に採用しない。
取消が間に合わず処理が完了した場合は「取消済み」とし、状態欄に保存済みの完成品のパスを示す。
取消後に別の原因で失敗した場合は、失敗として理由を表示する。
ワーカーが終了するまで新規実行を無効にするため、GPU処理の終了前に次の要求を実行しない。
処理中にウィンドウを閉じた場合も、取消を要求し、終了を待ってから閉じる。
開始前の基準記録・ファイル検査は実行スレッド内にあり、取消の反映はその検査を抜けた時点になる。

## 検証結果

```powershell
python -B -m unittest discover -s scripts/tests
ruff check scripts
python -B scripts/art_gui_verify.py --output-dir build/art/m4-validation-new
```

回帰テストは73件成功し、Ruffも成功した。
追加の[GUIテスト9件](../scripts/tests/test_art_gui.py)は、保存値とseed、全効果0、未対応モデルの拒否、未反映表示、ホイール操作、進捗と結果の表示、取消と古い通知、間に合わなかった取消、失敗後の実行、終了待ち、VFRの左右同期と一時停止中の再描画を検証する。
子プロセスがコンソール窓を開かないことは、処理基盤のテストで起動フラグを確認している。
Qtは自動検証用の`offscreen`環境を使った。ネイティブのファイル選択ダイアログのクリック操作と`.pyw`のダブルクリック操作は自動化していない。

実GPUでは、採用済み`melt-16`に入力ノイズ6と時間変化を加えた。
`test/test.mp4`の0.017〜0.05秒のプレビュー2フレームが、0〜0.08秒の本番5フレームの対応画素と一致した。
GUI設定を再読込した後の再生成、GPU推論中の取消、欠落入力による失敗、その後の再生成も成功した。
取消記録で元動画のハッシュ不変を確認し、処理中もQtイベントループが継続した。
[結果JSON](../build/art/m4-verified-2/summary.json)、[画面画像](../build/art/m4-verified-2/gui.png)を保存した。
さらに別PythonプロセスでGUIを生成し、[復元した全操作値](../build/art/m4-verified-2/restored-settings.json)が保存値と一致することを確認した。
レビュー修正後に同じ実GPU検証を再実行し、[再検証の結果JSON](../build/art/m4-verified-3/summary.json)でも全項目が成功した。

先行試験の0〜0.067秒は、末尾フレームの表示時間がMatroskaの1ms精度に収まらず、既存の衝突検査で失敗した。
この検査は変更せず、本番比較の試験区間を0〜0.08秒にした。
長区間・音声・最終配布構成を含む一連の制作確認は、ロードマップのM5で行う。
