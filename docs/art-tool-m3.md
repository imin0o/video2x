# M3 時間変化と本番動画

2026-09-14。元動画から区間を選び、時間変化を適用して、音声付きの等倍または2倍動画を書き出す処理を追加した。
R14〜R17の実装、技術検証、制作者による受入を終え、M3を完了した。
受入条件A07のちらつきとA09の許容待ち時間は、いずれも承認済み。

## 区間指定と書出し

既存のM0基準記録から、GPU、タイル、演算精度を読み込む。
`--input`には本番の元動画を指定する。
開始時刻を含み、終了時刻を含まない区間でフレームを選ぶ。
`--end`を省略すると末尾まで処理する。

```powershell
python -B scripts/art_process.py --recipe build/art/m1-source-color/melt-16/recipe.json --baseline-dir build/art/m2-baseline-2 --input test/test.mp4 --start 0 --end 5 --input-noise 6 --time-mode smooth --period 4 --phase 0.15 --modulation-depth 0.7 --output-scale 2 --output-dir build/art/my-production
python -B scripts/art_process.py --replay build/art/my-production/run.json --output-dir build/art/my-replay
```

出力先には未使用のディレクトリを指定する。
`result.mkv`と同名の`result.json`、実行中から更新される`run.json`、全設定を保存した`recipe.json`が生成される。
`--replay`では元動画、区間、設定、環境を復元し、映像の画素ハッシュと音声のPCMハッシュを照合する。
処理スクリプト、CLIとDLL、FFmpeg、Python依存、GPU環境が変わると再生成を拒否する。
コード更新前の記録は、新しい環境でレシピから処理し直す。

## 元時刻と時間変化

元動画のコンテナ開始時刻を0秒とし、各フレームのPTSを有理数で記録する。
区間を切り出しても、入力ノイズの時刻と座標は元動画上で変わらない。
復号は元動画の先頭から行い、途中シークによる復号履歴の差を避ける。
そのため、後方の区間では先行フレームの復号時間もかかる。

推論用の一時動画にはフレーム順に1秒間隔の時刻を付ける。
時間変調は別に保存した元時刻を参照し、最終出力で元のVFR時刻へ戻す。
中間ファイルは視聴用ではなく、元時刻とフレーム順の照合用に保持する。
プレビューでも元解像度と本番のタイル条件で推論する。

| 設定 | 意味 |
|---|---|
| `time_mode=fixed` | 全フレームで同じノイズ場を使う |
| `time_mode=smooth` | 二つの固定ノイズ場を余弦曲線で補間する |
| `time_mode=smooth-constant` | 補間時の分散を正規化する既存の試作モード |
| `modulation_depth` | 補間幅0〜1。0では固定と一致。既定値1で従来の動作を維持 |
| `period` / `phase` | 周期は秒、位相は周期に対する割合 |
| `modulation_target` | `input_noise`のみ。重みと特徴は時間変調しない |

2 passの場合は元寸法へ戻してから無改変モデルへ再入力する既存の順序を保つ。
等倍指定でも推論は2倍で行い、色の仕上げ後にLanczosで元寸法へ戻す。
等倍出力の原像保持量は寸法変換後に適用し、保持量1では元の画素に戻す。

## 映像と音声の出力契約

対応入力は正方画素の8ビットSDR、RGBまたはBT.601／BT.709系の色変換とする。
HDR、未対応画素形式、未対応の色行列は開始前に拒否する。
YUVの色行列が未指定の場合はBT.601として変換する。
出力はフルレンジBGRの可逆FFV1、Matroska形式になる。

出力の開始基準は指定した開始秒であり、先頭フレームがそれより後なら、その差を維持する。
Matroskaの時刻は最寄りの1msへ丸め、元の有理数時刻もJSONへ保存する。
丸めにより二つのフレームが同じ時刻になる区間は失敗として検出する。
全フレームの画素、時刻、寸法に加え、最終フレームの表示終了時刻を確認してから完成品にする。
FFmpegがコンテナの既定フレーム長を整数msへ切り下げる場合は、末尾時刻の差を1msまで許し、指定値と復号値を両方記録する。

`--audio pcm`が既定値で、全音声トラックを同じ元区間で切り、PCM float32に変換する。
圧縮音声のパケット境界に依存せずに切り出すため、音声のストリームコピーは行わない。
サンプルレートとチャネルを維持し、映像に対する遅延も保持する。
復号したサンプル数と先頭、末尾の時刻を元音声と照合する。
`--audio omit`で音声を明示的に除外できる。

## 進捗と取消

CLIは処理段階、処理済みフレーム数、経過時間を標準エラーへ出し、`run.json`も更新する。
共通APIの`Session(on_progress=callback)`でも同じ通知を受け取れる。
GUIからは別スレッドの`Session.cancel()`、CLIからはCtrl+Cで取り消す。
取消時は子プロセスの終了を待ち、`cancelled`と取消応答時間を保存する。
失敗時は`failed`、理由、推論ログの末尾を記録する。
出力は検証完了まで`.partial.mkv`とし、失敗や取消で`result.mkv`を作らない。

回帰テスト58件、Ruff、差分の空白検査が成功した。[テストログ](../build/art/m3-verified/tests.log)、[静的検査ログ](../build/art/m3-verified/lint.log)。
単体検証には、非フレーム境界の区間、0でないコンテナ開始時刻、VFRの長い表示間隔、単一フレーム、複数音声、AAC、遅延音声、音声のない区間、元PCMサンプルとの一致、等倍での原像復帰を含める。
GPU検証では本番5秒と途中プレビューの画素照合、2 pass、再起動後の映像と音声の一致、取消と例外後の再生成を確認する。
メモリ不足はGPU処理後に`MemoryError`を注入する試験であり、実GPUのメモリを枯渇させる試験ではない。
GPU検証は全項目成功した。[結果JSON](../build/art/m3-verified/summary.json)。
本番の300フレームに対して途中4フレームが推論直後と最終出力の両方で一致し、VFRの2 passでも対応5フレームが一致した。
取消と注入例外の後、および別Pythonプロセスへの再起動後にも、19フレームと音声のハッシュが一致した。

## 実測と制作者の確認

測定環境はWindows、RTX 4070 Ti SUPER 16GB、ドライバ610.62、タイル200、TTA無効。
入力は`test/test.mp4`の1920×888、60fpsで、本番5秒は3840×1776の300フレームへ出力した。
採用済み`melt-16`に入力ノイズ6、周期4秒、位相0.15、変調幅0.7を設定し、同じ条件の最終検証を1回測った。

| 測定対象 | 実測 |
|---|---|
| 5秒の本番出力全体 | 441.2秒（7分21秒） |
| 単フレームの等倍出力全体 | 3.90秒 |
| 本番のモデル読込 | 170.9ms |
| 本番の初回フレーム推論 | 113.9ms |
| 2フレーム目以降の平均推論 | 105.8ms |
| 本番の出力エンコードと音声処理 | 21.96秒 |
| GPU推論中の取消応答 | 38.8ms |
| GPUメモリの観測最大値 | 本番2237MiB、単フレーム2406MiB |

全体時間には、元動画の復号、ノイズと色の処理、中間動画の可逆圧縮、画素の照合を含む。
GPUメモリ値は200ms間隔で測ったデバイス全体の使用量で、他アプリを含み、プロセス単独の厳密なピークではない。
出力の指定末尾は5秒、FFmpegの整数msによる復号末尾は4.999秒、音声は44.1kHzの220500サンプルだった。
